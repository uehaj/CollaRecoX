## 3. 現在のセキュリティ／セッションモデル（要点）

- **アクセス＝ケイパビリティ（リンクシークレット）**: 推測不能な sessionId を知る者だけが room に到達。
  room 名は `transcribe-editor-v2-<sessionId>`。
- **配信権 = hostToken**: 配信(`/api/realtime-ws`)は hostToken 保持者のみ。サーバーは HMAC で**ステートレス検証**
  （セッションを保存しない。秘密鍵 `SERVER_SECRET` のみ保持）。
- **編集**: Hocuspocus(yjs-ws)。`onAuthenticate` は `COLLAB_AUTH_TOKEN` 未設定時は誰でも可（=sessionId を知れば編集可）。
- **Yjs文書は永続化なし**: `onLoadDocument`=null、`onStoreDocument`/DBなし、クライアントの y-indexeddb もなし。
  → room への最後の接続が切れると文書はメモリから消え、内容は失われる。再接続時は空から開始。
- **列挙**: 外部からは不可（一覧APIは410、y-websocketに列挙操作なし、IDはUUIDで推測不可）。
  サーバー内部は `hocuspocus.documents` で列挙可能（`server.js:617` にデバッグログ）。

## 4. 運用上の必須事項（重要）

- **本番では `SERVER_SECRET` を必ず設定**（未設定だと配信権検証がスキップされる）。`openssl rand -hex 32` 等。
- 任意: `COLLAB_AUTH_TOKEN`（編集接続の共有トークン）、`ALLOWED_WS_ORIGINS`（オリジン許可リスト）。
- いずれも `.env.example` に記載済み。
- `SERVER_SECRET` 漏洩時は任意 sessionId の hostToken を偽造可能＝鍵管理が最重要。
  鍵を変更すると既存の全 hostToken が無効化される（失効は個別不可）。
